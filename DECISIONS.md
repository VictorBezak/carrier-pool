1. (USER) When the shared carrier pool is activated, if 2 brokers have history with the same carrier, each broker will continue to only see their history with that broker. The only difference will be that if the other brokers participating in the pool have data for carriers that the other broker does not have any history with, then that carrier data will begin showing for the other broker for the first time. So if there is overlap, then the broker continues to see only their history with the carrier, but if there is no overlap and the carrier is completely unknown to the broker, then it will begin showing. Of course, this is while continuing to respect our constraint that broker data can not leak to other brokers -- if they opt-in to the shared carrier pool, then they will only be sharing data for those carriers.

2. (AGENT) BrokerOS carrier account records in the documented TMS C export do not include MC/DOT identifiers. Cross-system carrier identity in the synthetic data is therefore only provable between FreightFlow and HaulDesk, where those fields exist in the provided schemas. BrokerOS carriers should not be matched into a shared carrier pool by invented authority fields.
